# Permanent core-only release policy (v1.0.69)
Every production APK, including the canonical legacy filename, is lightweight. The historical thin filename is a byte-identical alias. The update manifest marks coreOnly=true and does not offer a larger APK. This also ensures older OTA clients download the core by default. All optional media are pinned to the signed resource catalog (commit, size, SHA-256), downloaded to persistent filesDir, verified and reused. Existing resource manager supports missing/damaged, selection, retry, deletion and Wi-Fi policy. Portraits are grouped by race; missing portraits do not block character creation.
New heavy assets must go in gallery/, maps/, portraits/, or media/<group>/; register runtime readers with ResourceStore. Unknown assets fail the build; do not add optional files to res/drawable, assets core, or native bundles. Minimal mandatory lore, fonts and fallback icon atlas remain. CI strips optional files before debug and signed builds, validates APK contents, and does not build a full resource-filled package. Existing signed resource packs remain local across updates. Portraits previously included in v1.0.65–68 were not registered in that version's migration catalog, so they need one-time download when upgrading directly; no saves are touched. Device tests remain necessary.
